# Customer Communication Layer — Extension Demo

This is a demonstration extension beyond the core assessment scope. It shows the
full request → clarify → confirm → final-quote loop that would run in a real
sales workflow. Nothing in the core pipeline (resolution logic, price anomaly
detection, embedding retrieval, quote generation) was changed to support this.

---

## What was built

### `generate_customer_email.py`

Runs Steps 2-4b of the existing pipeline (email parsing, historical quote
retrieval, catalog resolution, price anomaly check), then drafts a customer-
facing reply email from the result.

The email splits into two sections based on what the pipeline returned:

- **Resolved items**: stated plainly with product name, quantity, and unit price.
  No internal pipeline details (no similarity scores, no source names).
- **Unresolved items**: handled differently depending on why the item didn't resolve:
  - *Ambiguous* (multiple close candidates): lists the real options by name, asks
    which the customer wants.
  - *Size not in catalog*: names the closest match, asks the customer to confirm
    availability in their size or suggest an alternative SKU.
  - *No catalog match*: says plainly the item isn't currently carried. Offers a
    nearby alternative only when one genuinely exists.
  - *Price anomaly*: says only that pricing is being confirmed with the supplier.
    Does not explain internal data quality issues to the customer.

Usage:
```
python quotes/generate_customer_email.py \
    --email quotes/tests/test_email_live.txt \
    --out   quotes/output/email_live.txt
```

### `process_customer_reply.py`

Takes the customer's clarifying reply alongside the original email and produces an
updated quote. Three paths per previously-unresolved item:

1. **Customer confirms a specific option** — re-resolves directly to that catalog
   item by name (skips similarity search, since the customer told us which one),
   then runs the confirmed item through the price anomaly check before quoting it.
2. **Customer removes the item** — drops it from the resolutions list entirely.
3. **Customer gives partial info that still doesn't fully resolve it** — keeps
   the item unresolved with an updated, more specific reason.

The final quote is regenerated by calling `generate_quote.py`'s generation step
directly. No quote logic is duplicated.

Usage:
```
python quotes/process_customer_reply.py \
    --original-email quotes/tests/test_email_live.txt \
    --reply-email    quotes/tests/test_email_live_reply.txt \
    --out            quotes/output/quote_live_updated.txt \
    --email-out      quotes/output/email_live_updated.txt
```

## Test case

`test_email_live.txt` is the existing live test email (nursing school, 2 items
requested: nitrile gloves medium, venipuncture training arms, and a "SuperFlex
Deluxe Manikin"). The venipuncture arm resolved cleanly; the gloves were
unresolved (medium size not confirmed in top catalog results); the manikin was
unresolved (ambiguous between two Simulaids products in different categories).

`test_email_live_reply.txt` is the customer's reply:
- Confirms Adenna Nitrile gloves in medium are acceptable — triggers a re-resolve
  by name, which should return the Adenna product at catalog price.
- Removes the manikin request entirely — dropped from the updated quote.

The updated quote should show two resolved line items (venipuncture arm + gloves)
and no unresolved section.

## Design notes

The re-resolution threshold for customer-confirmed items is 0.65 rather than the
normal 0.72. When the customer has named a product explicitly, the embedding
lookup is a catalog name search, not a description-to-product match. A slightly
lower bar is appropriate because the lookup text is the catalog product name
itself, not a vague description. If even that fails, the item stays unresolved
with a rep-verification note.

The price anomaly check runs on newly resolved items from customer confirmation
the same way it runs on the original resolution pass. A customer confirming a
product doesn't bypass the anomaly gate.

The customer email generator deliberately does not expose pipeline internals:
no similarity scores, no source names, no mention of catalog resolution or
anomaly detection. The customer sees only product names, options, and questions.
